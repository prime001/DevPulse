# DevPulse — Engineering Command Center

## Problem

Work is scattered across multiple projects, ADO boards, git branches, and mental context. There's no single view that answers: "What should I work on right now, and where do things stand?"

## Solution

A terminal dashboard that runs on SSH login (or on-demand) and shows:
- Project status across all repos (branch, clean/dirty, test health)
- ADO ticket priorities and PR alerts
- Cross-project phase tracking with blockers
- A single prioritized "what to do next" list

## Standard Bobaverse rules

These apply to *every* Bobaverse project. Don't re-flag them as findings.

- **Email = SES only.** Never Gmail SMTP, app passwords, or SendGrid (except RealEstate, which is an active migration). Use `boto3.client('sesv2')` from a verified identity. Sending-domain ⊥ purpose (apex for transactional, `outreach.<root>` for cold). See `/opt/wiki/services/email-system.md`.
- **Secrets via env, never in source.** `os.environ.get(K, "")` with empty-string fallback, guard at call site. `.env` files are git-ignored. Verify with `git ls-tree origin/master .env` (must return empty). Service-specific `.env` paths must be registered in PrimeRestorer env-backup staging.
- **No direct commits to master / main.** Pre-commit hook `enforce-branches.sh` blocks this. Use feature branches; PrimeBus auto-merges on Gandalf ≥7/10 + tests pass.
- **`-- Claude / <Host> (Bob-N)` signoff on operator-facing outbound only.** Customer-facing email bodies (retainer, drips, transactional) DO NOT include the Bob-N footer. Operator/Discord/admin channels keep it.
- **Atomic state transitions.** SQL UPDATEs conditioned on prior status with `WHERE prior_status = ? AND revoked_at IS NULL`; check `rowcount`. Never read-then-write across separate transactions for state machines.
- **Bearer values redacted in logs.** Tokens, request_refs, OAuth state values use a SHA-256 prefix helper, not raw strings.
- **Fail-closed config validation at startup.** When a feature flag is on, validate required settings; force-disable the flag on misconfiguration and log loud rather than 500ing at request time.


## Score-rule self-discipline

- **≥7 approved** → auto-merge.
- **5–6 blocked** → patch real issues IF trajectory is converging upward. If oscillating 5↔6 with new edge cases each round, 3 patches is plenty — FF-bypass.
- **<5 blocked** → stop. FF-bypass the last commit that scored ≥5.

When this file documents a pattern as "intentional" or "FF-bypassed residue," don't re-flag without new evidence.
